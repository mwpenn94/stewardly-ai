## Rationale

The cost-tier reference distinguishes truly free open-source/government data sources (FRED, edgartools, FinanceToolkit, etc.), freemium tools (Polygon, FMP, Tiingo), and paid-only enterprise tools (Bloomberg, Plaid, CANNEX). Stewardly's sourcing decisions should explicitly track cost tier alongside authority tier so that:

1. Vendor cost dependency is visible at sourcing time, not at vendor-bill time.
2. Tier 0 Instant and Tier 1 Quick-check surfaces don't accidentally depend on $24K/yr enterprise data that breaks the surface if budget lapses.
3. Scope #7 integration roadmap can prioritize the no-free-alternative paid integrations (Plaid, CANNEX) and the highest-leverage free integrations (FRED, edgartools, GLEIF, OpenFIGI) ahead of freemium tools where free tier is sufficient.
4. Compliance/audit reviewers can answer "what does it cost to keep this default fresh?" alongside "how authoritative is this default?"

This is a governance dimension (axes meta-framework Axis 4), naturally extending the existing DoD 4h gate 6 (regulatory half-life flagging) into vendor-cost-dependency flagging.

## Apply: Scope #4 DoD 4b extension

In v2.6 DoD 4b (Defaults-from-industry-data refinement, preserved from v2.2/v2.3), append after the existing four dimensions:

> **Sourcing-tier dimension (v2.6.1):**
>
> Every default value tracks its source's cost tier (🟢/🟡/🔴) per `docs/reference/FINANCIAL_DATA_TOOLS_TIERED.md` alongside the existing authority-tier classification.
>
> **Sourcing policy:**
> - Prefer 🟢 FREE sources first when authority-equivalent. Government sources (FRED, BLS, Treasury, BEA, SEC EDGAR) are simultaneously highest-authority and zero-cost; there is no reason to wrap them in a paid vendor.
> - Use 🟡 FREEMIUM sources during development and prototyping; flag for paid-tier promotion when production scale or commercial use exceeds the free tier.
> - Use 🔴 PAID sources only when (a) no meaningful free or freemium alternative exists for the data domain, OR (b) the paid source has authority or coverage advantages that justify the cost AND the cost is budgeted.
>
> **Cost-tier × complexity-tier alignment** (informational guidance, not enforcement):
> - **Tier 0 Instant** and **Tier 1 Quick-check** surfaces: 🟢 FREE sources only. A Tier 0 surface that breaks because a paid subscription lapsed is a design failure.
> - **Tier 2 Current engine** surfaces: 🟢 FREE preferred; 🟡 FREEMIUM acceptable when documented; 🔴 PAID only with explicit justification.
> - **Tier 3 Advanced cascades** and **Tier 4 AI+integrations**: any tier acceptable; declare cost dependency at sourcing time.
>
> **Per-default tracking** in `CALCULATOR_PARITY.md` Section G (defaults refinement) gains a `source_cost_tier` column: `🟢 | 🟡 | 🔴 | n/a:<reason>`. Defaults sourced from multiple tiers (e.g., free source primary + paid source fallback) declare `🟢→🔴` notation with both source links.

Add to merge gate (Step 7) in v2.6 loop:

> - **Cost-tier policy violation:** scope-#4 pass ships a Tier 0 or Tier 1 surface defaults sourced from 🔴 PAID source without explicit user override → block.
> - **Untagged default:** scope-#4 pass ships a default without `source_cost_tier` value committed → block.

## Apply: Scope #7 integrations roadmap (NEW substantive change)

Scope #7 is preserved as maintenance-floor for own surfaces (per v2.5/v2.6), but its capability roadmap (which integrations to build / maintain when scope #4 Tier 4 demand surfaces a `pinnacle-infrastructure-gap`) is now explicitly cost-tier-prioritized.

Add to v2.6 scope #7 section:

> **Integration capability prioritization (v2.6.1):**
>
> When `pinnacle-infrastructure-gap` triggers scope #7 capability work, target selection follows this priority:
>
> **P0 — Build first** (no free alternative + high Stewardly leverage):
> - Plaid (banking aggregation; no real free alternative; foundational for Tier 4 cross-client analytics)
> - SEC EDGAR via edgartools (filings; foundational for compliance-aware flagging)
> - FRED (macro defaults; zero-cost; foundational for Tier 0/1 surfaces across Retirement, Tax, Estate)
> - GLEIF + OpenFIGI (entity / instrument identifier resolution; zero-cost; foundational for cross-client portfolio analytics)
> - NAIC Financial Data + FFIEC (carrier and bank data for insurance-side defaults; zero-cost; foundational for Protection surfaces)
>
> **P1 — Build when demand surfaces** (free or freemium with strong Stewardly fit):
> - Empower Personal Dashboard (free PFM ingestion; covers ~40-50% of consumer PFM market alone)
> - EveryDollar (free + Premium for Ramsey clients; high relevance to stewardship-aligned client base)
> - OpenBB Platform (open-source unified market data abstraction; replaces multiple paid APIs in many use cases)
> - GHL (already in Stewardly stack; deepen integration)
> - Wealthbox or Redtail (advisor CRM; freemium tier for prototyping; paid for production)
>
> **P2 — Build when explicitly justified** (paid-only with no free alternative):
> - CANNEX (annuity quote engine; required for high-fidelity annuity flooring in Tier 3/4 retirement surfaces)
> - Wink Intelligence (annuity research; pairs with CANNEX)
> - Holistiplan (tax return parser; high productivity gain but build-vs-buy tradeoff)
> - FP Alpha (cross-document analysis; same tradeoff)
> - eMoney / RightCapital (compliance-audited planning; primarily integration target if migrating from existing book)
>
> **P3 — Defer indefinitely** (enterprise-only with no near-term Stewardly demand):
> - Bloomberg / Refinitiv / FactSet (enterprise market data; only relevant if Stewardly enters institutional buy-side market)
> - CRSP / Compustat / OptionMetrics (academic/institutional data; only relevant for back-testing / research surfaces)
> - Addepar / Orion / Black Diamond (enterprise PMS; only relevant for white-label / multi-tenant institutional deployments)
>
> Aging-review every 50 passes re-evaluates this prioritization based on current `PINNACLE_INFRA_GAPS.md` demand signals + cost-tier-doc updates.

## Summary of behavioral change

- **Defaults and references gain a cost-tier dimension** alongside existing authority-tier tracking. Every default in scope #4 declares whether it depends on a free, freemium, or paid source.
- **Tier 0 and Tier 1 scope-#4 surfaces are protected from accidental dependency on paid sources** via merge gate.
- **Tier 4 surfaces show vendor-cost transparency** to advisors, not bury it in compliance documentation.
- **Scope #7 integration roadmap is explicitly prioritized** with 5 P0 integrations defined (Plaid, edgartools, FRED, GLEIF + OpenFIGI, NAIC + FFIEC), P1/P2/P3 sequencing per Stewardly demand and cost rationality.
- **Convergence requires** sourcing-tier compliance + 5 P0 integrations live.
- **Aging review** keeps cost-tier classifications fresh as the vendor landscape evolves.

This adds a sourcing-governance dimension to scope #4 and scope #7 without modifying the foundational gate structure of v2.6, the 5 pinnacle scopes of v2.5, the 5 axes of v2.4, the taxonomy of v2.3, or any earlier structural decision.
